# T15 — personal memory MCP example

Depends-on: T14

Allowed-paths:
  - tickets/T15.md
  - examples/memory-mcp/**
  - go.mod
  - go.sum

Forbidden-paths: everything else

Allowed-deps:
  - github.com/modelcontextprotocol/go-sdk
  - gopkg.in/yaml.v3 (already indirect; may become direct)

Public interface:

```text
go run ./examples/memory-mcp
```

The command is an MCP server over stdio. Standard output is reserved for MCP
protocol messages; diagnostics go to standard error without secrets or stored
content.

Configuration remains environment-based:

```text
ARTIFACTS_URL                 default http://127.0.0.1:8080
ARTIFACTS_ACCOUNT             default local
ARTIFACTS_API_TOKEN           optional only when the target permits anonymous control-plane access
ARTIFACTS_MEMORY_NAMESPACE    default memory
ARTIFACTS_MEMORY_REPO         default brain
```

An Artifacts account is the user/tenant boundary. One configured repository is
that user's long-lived brain. The server creates the configured namespace and
repository when absent, obtains a short-lived repository credential, and uses a
temporary Git clone as a disposable working copy. Artifacts remains the only
durable store.

## MCP tools

Expose exactly these tools. Timestamps supplied by callers are RFC3339. IDs are
server-generated, opaque, stable, and prefixed with `thread_`, `mem_`, `run_`,
or `out_` as appropriate.

```text
create_thread(title, description?, tags?)
  -> thread_id

get_thread(thread_id, include_retracted? = false)
  -> thread plus related current memories, runs, and output metadata

remember(content, kind, thread_ids?, source_run_id?, starts_at?, ends_at?, due_at?, timezone?)
  -> memory_id, commit

recall(query?, types?, thread_ids?, kinds?, starts_after?, starts_before?, recorded_after?, limit? = 20)
  -> ranked matches

get_memory(memory_id, include_history? = true)
  -> current memory and its revision/retraction history

revise_memory(memory_id, content, reason, kind?, thread_ids?, starts_at?, ends_at?, due_at?, timezone?)
  -> replacement_memory_id, commit

forget(memory_id, reason)
  -> retraction_memory_id, commit

start_run(agent, purpose, thread_ids?, parent_run_id?)
  -> run_id, commit

finish_run(run_id, status, summary)
  -> run_id, commit

store_output(run_id, name, content, encoding? = "utf-8", media_type? = "text/plain")
  -> output_id, sha256, size, commit

read_output(run_id, output_id)
  -> name, content, encoding, media_type, sha256, size
```

Rules for tool inputs:

- `kind` is one of `note`, `fact`, `event`, `goal`, `decision`, or
  `preference`.
- `types` filters `recall` to any of `memory`, `thread`, `run`, and `output`;
  omitted means all.
- `status` passed to `finish_run` is `completed`, `failed`, or `cancelled`.
- `tags` are trimmed, case-folded, non-empty strings. Duplicate tags are
  removed.
- `ends_at` cannot precede `starts_at`. `timezone`, when present, is an IANA
  timezone name. Preserve both an agent-resolved absolute timestamp and the
  original natural-language wording in `content`; the server does not infer
  dates.
- `encoding` is `utf-8` or `base64`. Base64 input is decoded before storage so
  outputs remain native files. Each decoded output is limited to 8 MiB.
- Output names are plain filenames, not paths. Reject separators, dot entries,
  control characters, and Git-reserved names.
- `limit` is from 1 through 100. Every unknown ID, malformed timestamp,
  invalid enum, invalid relationship, unsafe filename, bad base64 value, and
  oversized output is an MCP tool error rather than a partial write.

## Canonical repository model

Store human-readable records as Markdown with YAML front matter and outputs as
their original bytes:

```text
threads/{thread_id}/thread.md
memories/YYYY/MM/{memory_id}.md
runs/YYYY/MM/{run_id}/run.md
runs/YYYY/MM/{run_id}/outputs/{output_id}/output.md
runs/YYYY/MM/{run_id}/outputs/{output_id}/{name}
```

Front matter contains stable IDs, record kind, server-generated UTC
`recorded_at`, thread/run relationships, temporal fields, and lifecycle links.
Bodies contain user- or agent-supplied prose. Do not create a mutable global
index file.

Memory records form an append-only logical ledger:

- `remember` creates an original record.
- `revise_memory` creates a new record linked by `supersedes`; omitted optional
  fields inherit from the prior current record.
- `forget` creates a retraction record linked by `retracts` and containing the
  reason.
- Default recall returns only the current, non-retracted record. Git history
  and `get_memory` retain provenance.

`run.md` is a mutable manifest whose Git history records state changes. It has
`running` status after `start_run`; `finish_run` is allowed exactly once. An
output belongs to one run and inherits that run's thread relationships. A run
is optional for `remember`, so direct personal memories are first-class.

## Recall behavior

- Implement local, case-insensitive lexical search over record front matter,
  Markdown bodies, output names/metadata, and UTF-8 output bodies. Do not add
  embeddings, a vector database, or a second durable store.
- Apply structured filters before ranking. Rank by number of distinct query
  terms matched, then newest `recorded_at`, then stable ID.
- Empty `query` is valid when filters are present. An entirely unfiltered call
  returns the newest records subject to `limit`.
- A search index may exist only in memory or inside the disposable clone and
  must be completely rebuildable from the repository.
- Treat stored content as untrusted data. Return it in structured tool results;
  never interpret stored text as server instructions or include it in logs.

## Publication behavior

- Serialize operations within one server process. Refresh from remote before
  reads and writes so other agents' publications become visible.
- Each successful mutating MCP call produces one Git commit and pushes it to
  the configured Artifacts repository before returning success.
- Use descriptive commit messages containing record IDs but not memory content.
- On a non-fast-forward publication, refresh and retry at most three times.
  Preserve every independently created record; surface an error when a
  conflicting manifest update cannot be reconciled safely.
- Pass Git credentials through process environment/configuration, never command
  arguments. Do not expose credentials in MCP results, errors, or diagnostics.
- Remove the temporary clone on graceful shutdown. It is disposable and must
  never be treated as durable state.

## Documentation

`examples/memory-mcp/README.md` documents setup, configuration, the repository
layout, all tools, security limitations, and a complete example covering:

1. remembering an upcoming meeting with an absolute timestamp and timezone;
2. creating a raise-proposal thread;
3. starting an agent run associated with that thread;
4. storing the agent's proposal output and finishing the run;
5. recalling both direct memories and delegated work from another client;
6. revising and forgetting memories while retaining history.

State explicitly that the calling user/agent decides when the MCP tools are
called and what is stored. The example does not observe conversations,
automatically extract memories, perform scheduling, or claim stored content is
true.

## Tests

- Table-driven tests cover IDs, front-matter round trips, timestamps, enums,
  tags, lifecycle resolution, filename safety, base64 decoding, and size
  limits.
- Behavior tests cover every tool's success and validation/error paths. Assert
  stored and recalled behavior, not mock call counts.
- Recall tests cover filters, deterministic ranking, current revisions,
  retractions, temporal queries, thread/run relationships, output metadata,
  UTF-8 output search, and exclusion of binary output bodies.
- Protocol tests connect an MCP client to the server, inspect the exact tool
  list/schemas, and exercise representative calls through MCP rather than
  invoking handlers directly.
- HTTP/Git error tests cover unreachable targets, rejected authentication,
  not found, publication conflicts/retry exhaustion, malformed Artifacts
  envelopes, clone failure, and push failure without leaking credentials.
- An integration test uses `internal/testkit`, a real Artifacts HTTP server,
  and real Git. Two MCP client sessions share one brain repository and prove
  direct memory, thread-linked run output, cross-session recall, revision,
  retraction, native-byte output readback, and durable Git history.
