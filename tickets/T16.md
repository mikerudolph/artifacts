Public API:

```text
GET /client/v4/accounts/{account}/artifacts/namespaces/{namespace}/repos/{repo}/tree?ref={ref}&path={path}

ui.New(rest http.Handler) (http.Handler, error)
```

Rules:
- Repository materialization remains server-side through `repository.Manager.Read`; clients never fetch or unpack WAL packs.
- The path-oriented tree route resolves a commit ref, lists the root or requested directory, and returns the resolved commit, tree hash, path, and entries in the normal envelope.
- Existing hash-oriented tree, blob, file, and raw routes remain compatible.
- The development browser obtains namespaces, repositories, refs, trees, files, commits, and WAL entries only through the REST handler.
- Directory entries are navigable. File entries open a bounded, escaped text preview or a download response for binary/oversized content.
- Stored HTML, SVG, and other active content must not execute in the browser UI.
- Branch selection preserves the current repository view and reloads content from that ref.
- The WAL tab remains a storage diagnostic and is not presented as repository file content.

Tests:
- Path-oriented tree tests cover root, nested directory, missing ref, missing path, and file-as-directory errors.
- Browser behavior tests exercise it against a REST handler and cover navigation, escaped text preview, binary download, missing content, branches, commits, WAL, and REST failures.
- An end-to-end test evicts the disposable cache before a REST file read and proves reconstruction from published WAL.

Done:
- A repository populated through Git can be browsed recursively and its stored files viewed from `artifacts dev`.
- The UI no longer receives service or repository-manager dependencies.
- Existing content routes remain compatible.
- `make verify` is green; changed packages stay at or above 85% coverage and all complexity limits pass.

Blocked-if: a frozen storage interface, new dependency, or edit outside Allowed-paths is required
